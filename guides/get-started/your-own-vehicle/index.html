GET STARTED/YOUR OWN VEHICLE

Your own vehicle

Use this page for a vehicle that is not a Chaos Vehicles pawn. For a Chaos Vehicles pawn, the Crushform Chaos Vehicle Adapter reads the wheels from the movement component, and Quick start covers it.

Before you start

Section titled “Before you start”
  • The root component of the actor is the simulated body. Dents and paint are measured on it, and a dent needs a deform profile.
  • Set up the materials as in Quick start.
  • The wheels are components of the actor: a mesh, or a scene component that turns with the wheel.
  • For C++, add the Crushform modules you call to your Build.cs, as in Installation.

With the Crushform Vehicle Adapter

Section titled “With the Crushform Vehicle Adapter”

The adapter traces the ground under each wheel you list. It creates the dents and dirt, the glass, the tyres, the sounds, the prop breaking and the impact feedback, and answers their questions about the vehicle.

  1. Add › Crushform Vehicle Adapter. Add it to the actor.
  2. Set UCFVehicleAdapterComponent::Wheels: one FCFAdapterWheel for each wheel. In Details, expand Wheels and add one element per wheel. In each element, pick the wheel in the Wheel list, which shows the scene components of the actor, and set Radius to the tyre radius in centimetres. A radius of 0 means half the height of the wheel mesh’s bounds. Set the radius for a wheel that already turns.
  1. Set GroundChannel, the channel the wheels trace the ground on (Visibility by default), and GroundProbeMargin, 2 cm by default. The trace starts at the hub, so a tyre that is this far above the ground still touches it. Or call UCFVehicleAdapterComponent::SetWheels during the game with FCFAdapterWheelState values. It also works before BeginPlay.
  2. Set Authority and RamAllowanceMps. Server is the default: the server simulates the vehicle and judges its hits. With OwningClient, the machine that drives the vehicle simulates it and reports its hits, and the server accepts a report only when its speed change is at most the vehicle’s recent peak speed plus RamAllowanceMps (15 m/s by default), scaled up for a lighter body that gives way. Then set the profiles and the feature flags. An empty DeformProfile or TireProfile takes the project default. Every feature flag is on by default; each one switches off the component it names.
  3. Bind OnDamageChanged in Blueprint if the vehicle must react to damage. It fires when the body’s damage changes, and never without Dirt and Dents.

Tell the adapter what the vehicle does

Section titled “Tell the adapter what the vehicle does”

The adapter cannot see your controls, so tell it:

  • Call UCFVehicleAdapterComponent::SetBraking with a value from 0 to 1. The rolling effects throw more dirt while the vehicle brakes.
  • Call UCFVehicleAdapterComponent::SetCabinMuffled with true while the listener sits in the cabin. It muffles the rolling sound and the engine sound.
  • The engine sound reads five events: GetEngineRunState (Off, Cranking or Running), GetEngineRPM, GetEngineIdleRPM, GetEngineMaxRPM and GetEngineLoad. The adapter answers off and zero. Override them in a Blueprint subclass of the adapter, or in C++.

Feed it from your movement component

Section titled “Feed it from your movement component”

If your wheels are simulated by a physics system other than the built-in trace, override the four wheel events of the adapter: UCFVehicleAdapterComponent::BuildWheelContacts, CollectWheelMeshes, BuildTireWheels and BuildLoadRatios. The Chaos adapter does the same for Chaos Vehicles.

For each wheel, BuildWheelContacts fills one FCFWheelContact per frame:

  • Point: where the tyre touches the ground, in world space, cm. It is read only while bGrounded is true.
  • Radius: the tyre radius, cm.
  • bGrounded: false while the wheel is in the air. A wheel in the air leaves no dirt.
  • PhysicalMaterial: the ground under the wheel. Null takes the default rates.
  • SurfaceSpeed: the speed of the tyre’s surface, m/s, positive when it rolls the vehicle forward.
  • GroundSpeed: the speed of the hub over the ground, m/s. Below 0, the vehicle’s velocity is used.
  • WheelIndex: the wheel’s number, counted from 0. It stays the same for the wheel’s whole life.

CollectWheelMeshes returns the wheel meshes. They take dirt and never deform. BuildTireWheels returns each tyre’s mesh, physics radius and HostIndex, and bAcceptsPush; the host interfaces guide says when to set it. BuildLoadRatios returns the contact force over the nominal load, by HostIndex; a missing or negative entry holds that wheel’s load factor at 1.

Without an adapter: host interfaces

Section titled “Without an adapter: host interfaces”

Use host interfaces when your vehicle has its own component setup and you do not want the adapter. You add the Crushform components yourself, and you answer their questions in the actor or in one of its components. The interfaces live in the Crushform module, except ICFTireHost and ICFTireViewer (CrushformTire) and ICFEngineHost (CrushformEngine).

Which components to add

Section titled “Which components to add”
ComponentModuleWhat it needs
UCFDeformComponentCrushformA deform profile: without one it does nothing. The actor’s root component is the simulated body.
UCFGlassUnitsComponentCrushformThe glass panes, which are UCFGlassComponent children of the actor. The actor’s GetCrushformGlass returns this component. It needs the deform component.
UCFTireComponentCrushformTireICFTireHost on the actor. Without it the tyres stay round. A tyre profile, or the project default.
UCFRollingAudioComponentCrushformWheelICFWheelHost on the actor. Each surface’s sound comes from the project’s surface table.
UCFRollingFXComponentCrushformWheelICFWheelHost on the actor. Each surface’s effect comes from the project’s surface table.
UCFPropContactComponentCrushformThe actor’s root primitive as the body. ICFBreakerHost is optional.
UCFImpactFeedbackComponentCrushformImpactThe primitive whose hits it reports, set with SetObservedPrimitive. Its EventTag plays the sound; empty means no sound.
UCFEngineAudioComponentCrushformEngineICFEngineHost on the actor. A sound profile, or the project default.

On a vehicle body, the adapter uses UCFNetImpactFeedbackComponent instead of UCFImpactFeedbackComponent. It reports the body’s hits only on the machine that simulates the body, and the other machines play the relayed copy.

In the Add menu, the impact feedback components, CFImpact Feedback, CFNet Impact Feedback and the part one, are listed under Custom, not under Crushform.

The six host interfaces:

InterfaceAsked byAnswers
ICFDeformHostUCFDeformComponent, the net impact feedbackWhich machine simulates the body, the ignored actors, whether a report is plausible, which meshes deform, the wheel meshes, the glass
ICFWheelHostthe dirt layer, UCFRollingAudioComponent, UCFRollingFXComponentThe frame’s wheels, as FCFWheelContact values
ICFBreakerHostUCFPropContactComponentWhether this machine simulates the body, the contact body, the report route, the deform component a broken unit dents
ICFTireHostUCFTireComponentThe wheels, the offsets and pushes written back, the load ratios, the rig
ICFTireViewerthe tyre budget, on a pawnThe vehicle the pawn rides in, or null on foot
ICFEngineHostUCFEngineAudioComponentThe engine’s state: run state, RPM, idle and maximum RPM, load

A component finds its host in this order. First, the host set with SetCrushformHost before BeginPlay. Then the host registered for the actor in UCFHostRegistry. Then the actor itself, if it implements the interface. Otherwise there is no host. Each event answers with ECFHostAnswer: Default means the component decides as if there were no host, and Yes or No overrides that.

In Blueprint

Section titled “In Blueprint”
  1. Open the actor’s Blueprint and go to Class Settings. Under Implemented Interfaces, click Add and pick the interface, for example CFDeform Host, then CFWheel Host.
  1. The functions of the interfaces appear in My Blueprint under Interfaces › Crushform, with their C++ names without spaces, such as GatherCrushformWheelMeshes. Double-click one to implement it. An ECFHostAnswer member that you leave untouched returns Default. A list member that you leave untouched gathers nothing.
  1. GatherCrushformWheelMeshes has an output array, so it is a function. Build an array of the four wheel meshes and connect it to the output of the Return node.

In C++

Section titled “In C++”

Implement the interfaces on the actor, and override the _Implementation of each event you answer. This class answers the wheel meshes and the wheel contacts of a four-wheel vehicle.

The body of GatherCrushformWheelContacts traces down from each wheel’s hub and fills one FCFWheelContact per wheel. A wheel that is in the air keeps bGrounded false, and its Point and PhysicalMaterial stay unset.

Pitfalls

Section titled “Pitfalls”
  • A second host for the same actor and interface replaces the first one, with a warning.
  • A Blueprint host does not answer in the editor preview. The preview does not run its script, so the lattice layout in Details and the zone editor do not see its answers. Check the result in Play.
  • Do not call an interface event by name on an interface pointer. Use the Execute_ function, or the component’s accessor.

Check that it works

Section titled “Check that it works”
  1. Open the level with your vehicle and press Play.
  2. Open the console with the tilde key and run Crushform.Stats. It prints the atlas slots in use and the hit counters of every damageable actor.
  3. Run Crushform.Debug 1. It draws the damaged nodes of the body’s lattice. Crushform.Debug 2 draws all of them.
  4. Run Crushform.DebugImpact 10 <name> to hit the actor whose name contains <name> at 10 m/s, up to 100 m away. Without a name it hits the actor under the crosshair. It never hits the pawn you control, so check your own vehicle by driving into a wall, as in step 5 of Quick start. It is a cheat: every build except Shipping has it, the editor included.
  5. Drive across ground made of PM_CF_Mud. The wheels should react to the mud as the project’s surfaces table sets it.
