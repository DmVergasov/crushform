ИНТЕГРАЦИЯ/ПРОФИЛИ И ПРЕСЕТЫ

Профили и пресеты

Профиль — это ассет данных, который настраивает одну систему для одного типа кузова: как автомобиль получает вмятины, как деформируются его шины, как звучит двигатель. Плагин читает профиль из компонента, которому принадлежит система, поэтому в одном проекте может работать сразу несколько профилей. На этой странице перечислены классы профилей, место каждого из них, пресеты, которые плагин поставляет в папке Presets (/Crushform/Presets), и другие значения слова «пресет» в плагине.

На этой странице нет графа Blueprint. Профиль задаётся в значениях по умолчанию класса или в C++ до начала игры, и ни одна функция Blueprint не задаёт его компоненту: UCFDeformComponent::Profile имеет BlueprintReadOnly, а UCFTireComponent::SetProfile доступна только в C++.

Где задаётся каждый профиль

Класс ассетаЧто настраиваетЗадаётся вЗначение проекта по умолчаниюЗначение плагина по умолчанию
UCFProfileКак кузов получает вмятины, потёртости краски и грязьUCFDeformComponent::Profile или DeformProfile на адаптере автомобиляUCFSettings::DefaultProfile/Crushform/Presets/DA_CF_DefaultProfile

Остальные ассеты данных плагина являются определениями, а не профилями. Стеклянные панели принимают UCFGlassDefinition, разрушаемые объекты — UCFBreakablePropDefinition, деревья — UCFTreeConfig, а звуки ударов — UCFImpactFeedbackSet. У каждого из них есть своя страница в этом руководстве. Поверхности, которые задают грязь и звук качения для каждого покрытия, принимают ассет UCFSurfaces, указанный в UCFSettings::Surfaces.

Создавайте все эти ассеты через Add > Miscellaneous > Data Asset в Content Browser и выбирайте нужный класс. Плагин не регистрирует собственной фабрики и собственной категории ассетов.

Задание профиля кузову

Заголовок раздела «Задание профиля кузову»

Компонент без профиля ничего не делает. Для UCFDeformComponent это происходит без предупреждений: решётка не строится. Компонент читает свой профиль при начале игры, поэтому задайте его одним из двух способов:

  • В значениях по умолчанию класса Blueprint, в поле Profile в Details компонента.
  • В C++ между SpawnActorDeferred и FinishSpawning, до начала игры компонента.

У автомобиля с адаптером оставьте поле профиля адаптера пустым, чтобы взять значение проекта по умолчанию. Адаптер передаёт компонентам деформации и шин значение проекта по умолчанию, когда поле пустое. Компонент двигателя, если у него нет собственного профиля, тоже использует значение проекта по умолчанию. Явно заданное значение в поле адаптера всегда важнее.

Если профиль задан, но ни один меш владельца не может деформироваться, компонент пишет предупреждение и остаётся выключенным:

Обычная причина — список Include Tags, которому не соответствует ни один меш, или владелец, все меши которого исключены через Exclude Tags.

UCFProfile

Заголовок раздела «UCFProfile»

UCFProfile хранит настройки одного кузова. Его свойства сгруппированы по категориям, которые показаны на панели Details. В таблице перечислены свойства, определяющие внешний вид и поведение повреждений. Полный список находится в справочнике API.

Настройки вмятин описывают, как гнётся металл. Первыми меняйте Stiffness, MaxDentPerHit и MaxDisplacement. Держите MaxDentPerHit заметно меньше MaxDisplacement, чтобы повторные удары всё ещё углубляли вмятину. Затем проверьте материалы: их Max World Position Offset Displacement должен быть не меньше MaxDisplacement плюс амплитуда складок. Материалы и шейдеры объясняет это ограничение.

Зоны жёсткости

Заголовок раздела «Зоны жёсткости»

UCFProfile::StiffnessZones — это список боксов в пространстве корневого компонента. У каждой зоны свой Stiffness: значение 1 даёт вмятины такой же глубины, как у остального кузова, значение 3 даёт вмятины глубиной в треть, а 0.5 — вдвое глубже. У зоны также есть EdgeWidth, MaxDepth (ноль берёт MaxDisplacement профиля) и переключатель bMirrored, который распространяет зону и на симметричную сторону кузова относительно его центральной линии. Name нужен только редактору. Зоны задаются в Zone Editor, а Crushform.ShowZones 1 рисует их.

Заголовок раздела «UCFTireProfile»

У автомобиля с адаптером, когда поле TireProfile адаптера пустое, используется значение проекта по умолчанию DA_CF_DefaultTireProfile. Бюджет, который решает, какие шины деформируются, задаётся в Crushform Tire, а не в профиле.

UCFEngineSoundProfile

Заголовок раздела «UCFEngineSoundProfile»

UCFEngineSoundProfile хранит петли звука двигателя и то, как они воспроизводятся:

  • Layers: петли в любом порядке. Компонент сортирует их по оборотам, а слой без звука пропускается.
  • Attenuation: обязателен. Без него звук двигателя остаётся выключенным.
  • Coast Volume: доля полной громкости, которая слышна без нагрузки. По умолчанию 0.6.
  • Min Pitch и Max Pitch: самая низкая и самая высокая высота тона, на которой играет петля, относительно записанной скорости. По умолчанию 0.5 и 2.
  • Starter Sound и Shutdown Sound: петля стартера, пока двигатель прокручивается, и звук, когда работающий двигатель выключается.

Если у компонента нет профиля и нет значения проекта по умолчанию, двигатель остаётся беззвучным, и об этом пишется в лог.

Другие пресеты

Заголовок раздела «Другие пресеты»

В плагине слово «пресет» означает ещё три вещи. Ни одна из них не является профилем.

  • Пресеты зон — это именованные наборы значений зон для Zone Editor. Они хранятся в UCFEditorSettings::ZonePresets, в Project Settings > Crushform Zone Editor. У каждого есть Name, Stiffness, MaxDepth и EdgeWidth. Они существуют только в редакторе.
  • Пресеты отладочных повреждений заполняют кузов повреждениями в режиме отладки: Light даёт три мягких удара, Medium — шесть, Heavy — десять, а Wreck — восемнадцать ударов, близких к допустимому максимуму.
  • Пресеты отладочной грязи заполняют кузов смесью грязи в режиме отладки: Dusty — только пыль, Muddy — грязь с пылью в треть от этого количества, Snowy — только снег, а Wet — только влага.

Отладочные пресеты находятся в модуле CrushformDebug и ничего не меняют в вашем проекте. Они нужны, чтобы опробовать системы на панели отладки.

Проверка работы

Заголовок раздела «Проверка работы»
  • В Content Browser откройте профиль и проверьте, что в его Details видны группы, перечисленные выше.
  • Запустите Validate Assets для профиля. Разрешение, которое атлас не может вместить, или некорректные зоны жёсткости выводятся как ошибка.
  • В сборке, которая не Shipping, выполните Crushform.Debug 1 на кузове с заданным профилем. Его повреждённые узлы показывают, где кузов получил вмятину.

Решение проблем

Заголовок раздела «Решение проблем»

Вмятин не появляется, и в логе нет предупреждения

Заголовок раздела «Вмятин не появляется, и в логе нет предупреждения»

Причина. У компонента нет профиля. Решётка не строится, и для этого случая в лог ничего не пишется.

Решение. Задайте профиль в значениях по умолчанию класса или в C++ до начала игры. У автомобиля с адаптером задайте Deform Profile или оставьте поле пустым, чтобы взять DA_CF_DefaultProfile.

Лог сообщает, что разрешение ограничено

Заголовок раздела «Лог сообщает, что разрешение ограничено»

Причина. Разрешение не помещается в один слот атласа, поэтому решётка уменьшается. Слот вмещает не более ResX * ResZ узлов и не более ResY рядов.

Решение. Уменьшайте Resolution, пока решётка не поместится, или увеличьте размер слота в Project Settings > Plugins > Crushform > Atlas. Data Validation сообщает о той же проблеме как об ошибке.

Шины остаются круглыми

Заголовок раздела «Шины остаются круглыми»

Причина. У компонента шин нет профиля шин. Лог сообщает об этом только на уровне Verbose:

Решение. Задайте UCFTireProfile на компоненте шин или задайте Tire Profile на адаптере автомобиля, который при пустом поле берёт значение проекта по умолчанию.

Двигатель беззвучен

Заголовок раздела «Двигатель беззвучен»

Причина. На компоненте нет профиля звука двигателя, а в проекте нет значения по умолчанию. Лог сообщает:

Решение. Задайте UCFEngineSoundProfile на компоненте или задайте значение по умолчанию в Project Settings > Plugins > Crushform Engine. Профилю также нужен Attenuation.
