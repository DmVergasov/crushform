集成/宿主接口

宿主接口

车辆适配器会替你为车辆回答这些问题。当你没有适配器，或者你的游戏自带宿主时，请使用这些接口。自定义车辆介绍了适配器和一个完整的车轮宿主，核心概念中有汇总表。本页依次介绍每个接口：它会被问什么、默认回答什么，以及如何实现。

由谁回答，按什么顺序

Section titled “由谁回答，按什么顺序”

组件按以下顺序查找宿主，并通过宿主向其拥有者提问：

  1. 显式宿主，在 BeginPlay 之前用 SetCrushformHost 设置。仅限 C++。
  2. 在世界子系统 UCFHostRegistry 中为拥有者注册的对象。其 Register、Unregister 和 FindHost 仅限 C++。
  3. 拥有者本身，前提是其类实现了该接口。
  4. 没有宿主。此时组件以无宿主的车身身份作答。

自定义车辆用一段话给出了相同的顺序。

车辆适配器会把自己注册为它所实现的五个接口的宿主：ICFDeformHost、ICFWheelHost、ICFBreakerHost、ICFTireHost 和 ICFEngineHost。带有适配器的车辆无需为这些接口另设宿主。适配器不实现 ICFTireViewer，它属于玩家所乘坐的 Pawn。

未实现该接口的宿主会被拒绝并报错，详见本页末尾的故障排除一节。同一 Actor 和接口的第二个宿主会替换第一个，并给出警告。

在注册表中注册宿主

Section titled “在注册表中注册宿主”

在注册表中为某个 Actor 注册宿主后，该 Actor 的每个组件都能找到它，无需调用 SetCrushformHost。注册表是世界子系统，因此通过世界获取它。在 Actor 的 BeginPlay 中，将 Actor 自身注册为其车轮宿主，并在 EndPlay 中移除注册：

  • Unregister 仅在条目仍持有该宿主时才将其移除。
  • 重复注册同一宿主不会产生任何改变，也不会输出日志。
  • FindHost 在没有注册表时也能工作。此时，若 Actor 实现了该接口，它会以 Actor 本身作答。

返回的答案

Section titled “返回的答案”

每个答案都是 ECFHostAnswer：

值含义
Default按组件在无宿主时的方式决定。
Yes是。
No否。

在蓝图中未修改的事件，返回的答案与无宿主时相同。返回 ECFHostAnswer 的事件返回 Default。返回列表的事件不收集任何内容。GatherCrushformIgnoredActors 返回 false，这意味着拥有者所附着的 Actor 仍被忽略。

不要通过接口指针按名称调用接口事件。自定义车辆中展示了应改用的 Execute_ 调用。

Section titled “ICFDeformHost”

UCFDeformComponent 的晶格会向它提问，车身的 UCFNetImpactFeedbackComponent 也是如此。请在拥有者上实现它。

GatherCrushformIgnoredActors输出数组：永不使拥有者变形的 Actor；以及一个布尔值，用于替换拥有者所附着的 Actor假，且不收集任何内容

GatherCrushformWheelMeshes输出车轮网格数组。它们接收污垢，且从不变形无

ICFWheelHost

Section titled “ICFWheelHost”

车身的污垢层、UCFRollingAudioComponent 和 UCFRollingFXComponent 会向它提问。蓝图宿主每帧被询问一次，同一帧内的所有调用者共享其答案。该事件为每个车轮填充一个 FCFWheelContact，无论车轮是否着地：

  • 同一车轮的 WheelIndex 必须在各帧之间保持不变。
  • 悬空的车轮保持 bGrounded 为假。其 Point 和 PhysicalMaterial 不会被读取。
  • 只报告着地车轮的宿主也是正确的，但这样就永远看不到车轮离开地面。

没有宿主时列表为空，车身永远不会变脏。

蓝图。 在 Class Settings > Implemented Interfaces > Add 中添加接口，然后在 My Blueprint 中实现 GatherCrushformWheelContacts。它带有输出数组，因此是一个函数。下方的图表实现了它，运行时打印信息，并保持数组为空。请在你自己的图表中填充该数组。

C++。 如同上面的 Deform 代码块那样在类中声明重写，并给出定义。自定义车辆构建了一个完整的车轮宿主，其中包含从每个轮毂发出的射线追踪。

ICFBreakerHost

Section titled “ICFBreakerHost”

UCFPropContactComponent 会向它提问。它决定什么会被破坏，以及报告送往何处。它对拖车很有用，拖车的接触通过其牵引车来破坏道具。每个答案都有一个默认值，描述的是没有宿主的车身：

事件回答内容默认值
IsBreakerSimulatedHereECFHostAnswer：本机是否模拟该车身权威端
GetBreakerBody其接触会破坏单元的刚体空（null），即拥有者的根基元
GetBreakReportRoute其连接负责传递破坏报告的 UCFPropContactComponent空（null），即拥有者自身的组件
GetBreakerDeform被破坏的单元使其凹陷的 UCFDeformComponent空（null）：被破坏的单元永远不会使车身凹陷

ICFTireHost

Section titled “ICFTireHost”

UCFTireComponent 向它询问车辆的车轮，并将轮胎偏移量和推挤量写回宿主。宿主不保存任何轮胎状态。组件会记住它改动过的内容，并在自身移除时将每个偏移量还原。共有四个事件：

事件回答内容默认值
GatherCrushformTireWheelsFCFTireWheelDesc 数组：车轮的网格、其 PhysicsRadius、HostIndex、VisualOffset 和 bAcceptsPush无，即保持轮胎为圆形
SetCrushformTireWheelOffsets一次性接收组件改动过的偏移量：每个 OffsetCm 和每个 PushCm无
GatherCrushformTireLoadRatios按 HostIndex 给出的接触力与标称载荷之比。空数组表示没有力模型空
GatherCrushformTireRig与此 Actor 耦合的 Actor，包括其自身仅此 Actor

蓝图。 添加接口，并将收集事件实现为函数。下方的图表实现了 GatherCrushformTireWheels，运行时打印信息，并保持数组为空。

C++。 车辆上的两个收集函数：

推挤。 设置了 bAcceptsPush 的车轮，在轮辋否则会嵌入障碍物时，会按其 PushCm 移动，使轮胎凹陷绕过障碍物，而不是让轮辋陷入。只有当 SetCrushformTireWheelOffsets 在同一次调用中把 PushCm 应用到车轮网格上（采用车主坐标系），并且网格保持该推挤直到下一次调用时，才设置 bAcceptsPush。如果宿主忽略推挤，推挤就会一路增大到配置的 MaxPush。如果宿主让推挤过期，因为其他东西移动了网格，或使其父级相对于拥有者转动，凹陷就会偏离其应有的位置。轮辋半径取自轮胎材质的 RimRadius 参数，或取自配置的 RimRadiusOverride；两者都没有的车轮从不被推挤。

适配器。 UCFVehicleAdapterComponent 自行应用推挤，并在没有蓝图覆盖 SetCrushformTireWheelOffsets 之前，为其车轮报告 bAcceptsPush。覆盖了它的蓝图自行摆放车轮，不会获得推挤。在 C++ 中覆盖 SetCrushformTireWheelOffsets_Implementation 的子类，承担与任何宿主相同的职责：调用基类（它会应用 PushCm），或自行应用推挤，或覆盖 BuildTireWheels 并把 bAcceptsPush 报告为 false。基类在推挤到达时将其一次性转换到车轮父级的空间中。如果车轮的父级相对于车主转动（例如转向节），或游戏改写了车轮的相对位置，子类便不再携带轮胎会减去的那份推挤，于是应把 bAcceptsPush 报告为 false。

ICFEngineHost

Section titled “ICFEngineHost”

UCFEngineAudioComponent 每帧向它询问发动机状态。其答案为 FCFEngineState：

字段含义
RunStateOff、Cranking 或 Running

仅限 C++ 的接口

Section titled “仅限 C++ 的接口”

ICFBreakableHost 和 ICFBreakableUnitPart 使用 CannotImplementInterfaceInBlueprint 声明。请仅在 C++ 中实现它们。它们属于可破坏的碎片，两者的成员都列在 API 参考中。

检查是否正常工作

Section titled “检查是否正常工作”
  • 在非 Shipping 构建中，运行 Crushform.Debug 1，然后用 Crushform.DebugImpact 撞击车身。受损节点会出现在车身凹陷处，这说明形变宿主已作出回答。
  • 使用 Play In Editor 运行，并在 Output Log 中查看被拒绝宿主的错误与被替换宿主的警告。日志干净，说明每个宿主都已被接受。
  • 实现车轮宿主并设置好路面后，驾车穿过一段泥浆。污垢会附着在车轮和车身上。

车轮不沾污垢

Section titled “车轮不沾污垢”

原因。 要么车轮宿主没有收集到任何车轮，要么项目没有路面资产。没有路面资产时，任何车身都不会变脏。未实现收集事件的宿主会返回空列表，这也就是默认值。

解决。 实现 GatherCrushformWheelContacts，为每个车轮添加一个 FCFWheelContact。在 Project Settings > Plugins > Crushform 中设置 Surfaces。

在编辑器中调用接口事件失败

Section titled “在编辑器中调用接口事件失败”

原因。 该事件通过名称在接口指针上被调用，而其生成的函数体是一个 check。

解决。 如自定义车辆所示，通过 Execute_ 调用，或在蓝图中使用 Message 节点。
