损伤/玻璃

玻璃

作用

Section titled “作用”

Crushform 车身的每一块玻璃板都可能开裂、碎裂，并散落成玻璃碎片。车窗附近的命中会使其开裂，更猛烈的命中会使其碎裂；车身在玻璃板周围凹陷时，也可能使其开裂。裂纹会一直留在玻璃板上，直到车身被修复。

工作原理

Section titled “工作原理”

玻璃板是车身上的一个静态网格体，即一个 UCFGlassComponent。它没有自己的碰撞。射击或投掷的石块会击中车窗处的车身碰撞体，Crushform 会把这次命中匹配到它所到达的那块玻璃板，匹配范围为 Hit Reach Cm（UCFGlassDefinition::HitReachCm，新定义中为 15 cm）以内。

每块玻璃板是一个单元，有三个等级：完好、开裂和碎裂。玻璃板按名称编号，因此各端对每块玻璃板的对应关系一致。

有三种情况可以使玻璃板开裂。玻璃板的定义为每一种情况设定阈值：

  • 命中。 玻璃板附近的命中，其速度变化量达到 Crack Delta V（UCFGlassDefinition::CrackDeltaV）时使其开裂，达到 Break Delta V（UCFGlassDefinition::BreakDeltaV）时使其碎裂。低于开裂阈值的命中对玻璃没有影响。
  • 车框。 车身在凹陷时会向玻璃板周围弯曲（凹陷与晶格对凹陷有说明）。玻璃板盒体内所有节点中位移最大的那个，达到 Frame Crack Displacement Cm 时使玻璃板开裂。这些节点的平均位移达到 Frame Break Displacement Cm 时使其碎裂。
  • 关联部件。 车身的某个部件，例如挡风玻璃前方的引擎盖（铰接部件对铰接部件有说明），可以通过玻璃板的 Crush Link Box（UCFGlassComponent::CrushLinkBox）使其开裂。该盒体内最深的节点会在离它最近的边缘处使玻璃板开裂，平均值则使其碎裂。

车框和关联部件只有在车身凹陷时才会评估玻璃。因此，玻璃需要车辆适配器上的 Dirt and Dents 开启。适配器通过它找到玻璃板。关于适配器和晶格，参见核心概念。

碎裂前的开裂次数。 将 Cracks Before Break（UCFGlassDefinition::CracksBeforeBreak）设为某个数值，可使玻璃板在被命中开裂该次数后碎裂。设为 0 时，玻璃板不会按次数碎裂。只有命中计入次数，车框不计入，因此一个保留下来的凹陷不会随时间使玻璃板碎裂。

裂纹外观。 每块玻璃板最多保留四道裂纹。裂纹的半径随命中强度增长，范围在 Min Crack Radius Cm 与 Max Crack Radius Cm 之间。Crack Style 设定图案：网状、孔状或网格状。

外部命中。 子弹或投掷的石块只有在 Takes Point Damage（UCFGlassDefinition::bTakesPointDamage）开启时，才能使玻璃板开裂。随后，定义中的 Hit Responses 表决定每一种命中使玻璃板达到哪个等级。表中没有对应行的命中种类不会产生任何效果（UCFBreakableDefinition::HitResponses）。

碎裂。 碎裂的玻璃板会被隐藏，并散落成玻璃碎片。玻璃板被方形分块覆盖，离命中点最近的分块优先。每个分块的边长为 Shard Tile Cm，碎裂成 Shards Per Tile 个碎片。至多 Max Shard Tiles 个分块会变成碎片，因此碎片最多覆盖玻璃板上这么多个分块，其余部分则直接消失：五个 50 cm 的分块覆盖 1.25 m²，夹层玻璃预设即如此。每个分块会绕玻璃板的朝外轴旋转一个随机角度，这样两个分块的碎片不会排成一条线。Shard Shape 决定碎片的形状：颗粒是小块，如钢化玻璃；板块是平片，如碎裂而不飞散的夹层玻璃。每个碎片都是碎片网格体之一，随机选取并缩放到该碎片的大小。插件自带六块不规则的多边形板，从 SM_CF_GlassShard_01 到 SM_CF_GlassShard_06，用 M_CF_GlassShard 绘制，那是边缘更亮的透明玻璃。

谁负责绘制。 服务器判定玻璃的状态，并复制裂纹，每一个绘制裂纹的端都会显示它们。专用服务器判定玻璃板，但不绘制任何内容。修复会使每块玻璃板恢复完整，并清除其裂纹。

设置

Section titled “设置”
  1. 打开车辆的蓝图，例如你项目中 BP_VehicleAdvSedan 的副本。选中它的 Crushform Chaos Vehicle Adapter 组件。确认 Dirt and Dents 和 Glass 已开启。两者默认都是开启的。
  2. 创建一个玻璃定义。在 Content Browser 中选择 Add > Miscellaneous > Data Asset，选择 CFGlass Definition，然后为其命名。你也可以从 Plugins › Crushform Content › Presets 中复制一个自带的预设：DA_CF_GlassLaminated 或 DA_CF_GlassTempered。
  3. 检查定义中的碎片设置。没有碎片的定义会发出警告：碎裂的玻璃板会直接消失，而不产生任何碎片。请在编辑器工具蓝图或 Python 中调用 Build Glass Shards（UCFContentLibrary::BuildGlassShards，位于 Crushform|Content 分类）来生成碎片。该调用需要传入定义和一个碎片网格体列表；插件自带六个，由 Build Glass Shard Mesh（UCFContentLibrary::BuildGlassShardMesh）生成。
  1. 为每扇车窗添加一块玻璃板。在车辆的蓝图中，选择 Add › CFGlass，位于 Crushform 分组中。将其 Static Mesh 设为车窗的网格体，将 Definition 设为你的玻璃定义。把玻璃板附着在车身下，或附着在它所在的铰接部件下。
  2. 打开车窗的静态网格体，开启 Allow CPU Access。若不开启，弯曲或倾斜车窗的碎片会落在一个平面上，因为插件无法读取车窗的形状。
  3. 可选：设置玻璃板的 Crush Link Box，例如像轿车那样设为挡风玻璃周围的区域。对于引擎盖会折叠进去的玻璃板，也可以选择引擎盖。在 Crush Link Box 上勾选 Is Valid，然后以厘米为单位，在根组件的空间中设置其 Min 和 Max。盒体无效时，不会关联任何内容。在蓝图编辑器中选中玻璃板，即可在视口中看到绘制的盒体。该盒体只在蓝图编辑器中绘制，关卡和 PIE 中不显示。

使用

Section titled “使用”

用 Get Glass 从车辆适配器获取玻璃单元。只有 Glass 和 Dirt and Dents 都开启时，它才会返回结果。然后将 On Unit Level Changed（UCFBreakableUnitsComponent::OnUnitLevelChanged）绑定到一个自定义事件。该事件传递 Units、UnitIndex、Level 和 PreviousLevel。

每当某块玻璃板的等级发生变化时，每一端都会触发该事件。这也包括中途加入的玩家，他会收到已经开裂或碎裂的玻璃板状态。因此，应在处理函数中检查 Level，而不要假定该事件就意味着碎裂。不要由它启动一次性的特效。若要读取车身每一侧的凹陷程度，请使用损伤区域与事件。

在 C++ 中，可以让离某个点最近的玻璃板开裂或碎裂。这仅在权威端生效。

Deform 是车身的 UCFDeformComponent，WorldPoint 是世界空间中的 FVector。将 bBreak 设为 true，则改为使该玻璃板碎裂。如果没有玻璃板在该距离之内，或者什么都没有改变，函数返回 false。

检查是否正常工作

Section titled “检查是否正常工作”

在除 Shipping 之外的任何构建中，于编辑器内运行。Crushform.DebugImpact 不会命中你驾驶的车辆，因为轨迹会跳过它。开车靠近一辆停放的车，例如 Proving Ground 地图上的 BP_VehicleAdvSedan2，并将视野中心对准它的挡风玻璃。输入 Crushform.DebugImpact 8，速度变化量为 8 m/s。车窗上应出现裂纹，并听到开裂声。先设置 crushform.Impact.LogHits 1，即可记录每次命中的位置和强度。

然后在同一车窗上输入 Crushform.DebugImpact 15。在 15 m/s 时，玻璃板碎裂：它消失，碎片从车身上飞散。Crushform.RepairAll 会让玻璃板恢复完整。

故障排除

Section titled “故障排除”
  • 车窗附近的命中没有留下裂纹。 命中低于 Crack Delta V（新定义中为 5 m/s），或车辆适配器的 Dirt and Dents 已关闭，因此车框和关联部件从不评估玻璃。请加大命中力度，或降低 Crack Delta V，或开启 Dirt and Dents。
  • 碎裂的车窗消失了，但没有碎片。 定义中没有碎片。请按设置第 3 步，使用 Build Glass Shards 生成碎片。
  • 子弹穿过车窗却没有留下裂纹。 Takes Point Damage 关闭，或定义的 Hit Responses 表中没有该命中种类的行。请开启该开关，并为该种类添加一行。
  • 弯曲车窗的碎片飞向错误的平面。 车窗的静态网格体没有开启 Allow CPU Access，因此插件会为其套上一个平面盒体。请开启该选项，然后重新生成碎片。
  • 多块玻璃板同时碎裂时，缺了一些碎片。 每个世界只有一个碎片池：Max Live Debris Pieces（UCFBreakableSettings::MaxLiveDebrisPieces，默认 96）。当一次碎裂需要的碎片多于空闲数量时，新碎片会顶替最旧的存活碎片，包括前一次碎裂的玻璃碎片，这些碎片会提前消失。使用自带预设时，一块夹层挡风玻璃最多碎裂成 12 × 5 = 60 个碎片，一块钢化侧窗最多碎裂成 16 × 4 = 64 个，所以同时碎裂两块玻璃板就已超过 96。请在 Project Settings › Plugins › Crushform Breakable 的 Debris 分组中调高 Max Live Debris Pieces。碎片池的介绍见碎片。
  • 专用服务器上没有裂纹。 这是设计如此。专用服务器判定玻璃，但不绘制任何内容。请在客户端上查看裂纹。
